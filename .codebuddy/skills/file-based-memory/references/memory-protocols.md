# 文件记忆核心规则

## 5 条操作协议

1. **2 次操作规则**：每完成约 2 次重要搜索/阅读/决策后，更新一次持久化文档。不落盘意味着上下文压缩后这些决策永久丢失，下轮需要重新排查。

2. **先读后决策**：继续任务前，先读 `progress` 和相关 `findings`。跳过阅读会导致重复已排除的路径或覆盖已有的正确结论。

3. **三次错误协议**：同类失败达到 3 次，必须把失败模式写入 `findings`。不记录失败模式会让下一轮（或下一个 agent）陷入同一个坑。

4. **失败不重复**：已排除的方案必须记录，防止下轮重复尝试。每次重复尝试已排除路径都是上下文窗口的浪费。

5. **五问重启测试**：当上下文混乱时，用 `progress.md` 重新回答：
   - 现在在哪个阶段？
   - 做了什么？
   - 当前状态如何？
   - 遇到了什么阻断？
   - 下一步是什么？

## findings vs progress 边界

| 写入 findings | 写入 progress |
|---|---|
| 可复用的架构结论 | 当前任务阶段 |
| 稳定失败模式 | 已执行的操作 |
| 技术决策依据 | 测试结果/错误日志 |
| 关键资源链接 | 下一步计划 |
| 风险识别结果 | handoff 状态 |
