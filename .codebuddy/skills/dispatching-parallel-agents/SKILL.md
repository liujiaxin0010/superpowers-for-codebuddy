# 并行代理分发

本技能用于判断“现在能不能并行”，以及“并行时怎么分组、怎么防冲突、怎么收口”，而不是盲目多开几个子代理。

## 何时使用

以下情况适合并行：

1. 计划中存在 2 个以上低耦合任务
2. 每个任务都能明确允许修改范围
3. 每个任务都有独立验证命令
4. 汇总时有明确 owner 收口

## 何时不用

以下情况不应并行：

1. 所有任务都改同一个核心文件
2. 多个任务共享同一契约，且顺序未确定
3. 测试环境互相干扰
4. 用户要求严格串行推进

## 与其他技能的边界

1. 若需要长期 lane 管理、owner 收口、worktree 配套，优先 `parallel-delivery`
2. 若每个任务还需要 implementer + 双重审查闭环，优先 `subagent-driven-development`
3. 本技能更适合“当前轮次内的并行分发决策”

## 阻断条件

出现以下任一情况时，返回 `BLOCKED`：

1. 无法确认任务之间的依赖关系
2. 无法明确每个任务的文件边界
3. 没有统一 owner 或集成负责人
4. 共享核心文件但又无法重新拆分任务

## 并行分组协议

### 1. 先按依赖切组

把任务分成：

1. 完全独立组
2. 部分独立组
3. 必须串行组

### 2. 再按写集检查冲突

只有同时满足以下条件才可并行：

1. 不修改同一核心文件
2. 不依赖对方本轮输出
3. 不共享同一可变状态
4. 测试命令互不干扰

### 3. 最后控制并行度

默认最大并行度不超过 5。超过时：

1. 先并行第一组
2. 收到结果后再发下一组

## 子代理输入要求

每个子代理至少应拿到：

1. 完整任务规格
2. 允许修改的文件边界
3. 验证命令
4. 当前并行组内其他任务摘要
5. 统一的 owner 与收口说明

## 汇总与收口

所有并行任务完成后，必须做：

1. 文件冲突检查
2. 集成验证
3. 统一汇总问题与风险
4. 更新文档与进度

若发生冲突，不要让子代理自行拍板；统一升级给 Boss 或 owner。

## 禁止事项

1. 不要因为“看起来能省时间”就忽略依赖关系
2. 不要让共享核心文件的任务并行
3. 不要没有验证命令就并行分发
4. 不要没有统一收口人就启动并行
5. 不要把并行代理分发误当成长期 lane 管理
