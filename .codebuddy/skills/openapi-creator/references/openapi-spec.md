# 平台类 OpenAPI 接口定义规范

> 版本：2024.1.0 | 发布日期：2024-04-26 | 来源：浙江宇视科技有限公司

---

## 一、概述

本规范规定了平台类 Open API 接口制定时应遵循的技术规范，适用于所有使用平台类 Open API 接口进行软件开发的人员。

- **协议载体**：HTTP/1.1（RFC2616）
- **数据交换格式**：JSON（RFC8259）

---

## 二、数据类型

### 2.1 基本数据类型

| JSON 类型 | 描述 |
|-----------|------|
| `integer` | 整型，默认32位，64位需单独说明 |
| `number` | 数值型（浮点），默认单精度，双精度需单独说明 |
| `string` | 字符串 |

**规则：**
- **禁止**使用除 `integer`、`number`、`string` 之外的其他基本类型（如 `long`、`boolean`）
- 枚举类型字段需定义在数据字典中
- 枚举使用 `integer` 时值从 **1** 开始，保留 0 不用
- 枚举个数超过 10 个建议使用 `string`，较少且固定建议 `integer`
- 过大的整型/浮点型数字建议使用 `string`（JavaScript 安全整数范围：±9007199254740991）

**正例：**
| 参数名称 | 数据类型 | 是否必须 | 参数描述 |
|----------|----------|----------|----------|
| alarmType | string | 是 | 告警类型 |
| gender | integer | 是 | 性别 |
| deviceIndexCode | string | 是 | 设备编号 |

**反例：** 使用 `long`、`boolean` 等非标准类型 ❌

### 2.2 复杂数据类型

| 类型 | 描述 |
|------|------|
| `array` | 数组 |
| `object` | 对象 |

**规则：**
- 禁止使用除 `array`、`object` 之外的其他复杂类型
- 数组/列表必须使用 `array`，禁止用 `object`
- `array` 自带长度属性，**禁止**添加额外描述数组长度的字段

**反例：**
| 参数名称 | 数据类型 | 是否必须 | 参数描述 |
|----------|----------|----------|----------|
| supportProtocolNum | integer | 是 | 支持的协议个数 ❌ |
| supportProtocols | array | 是 | 支持的协议列表 |

### 2.3 特殊数据类型

#### 2.3.1 日期和时间
- 遵循 ISO8601 标准 TD/TZ 格式
- 正例：`2023-01-01T15:30:05Z`、`2023-01-01T15:30:05+08`
- 反例：`2023/01/01 15:30:05` ❌

#### 2.3.2 坐标
- 图像像素区域坐标使用**万分比**定义，范围：[0, 10000]

#### 2.3.3 温度
- 小数点保留**两位**

#### 2.3.4 文件
- 文件上传统一使用 `multipart/form-data`（RFC1867）
- URL 统一使用**绝对路径**
- 图片/文件内容建议通过 URL 返回，不宜用 JSON string BASE64 编码

## 三、请求与响应

### 3.1 URL 规范

**URL 路径格式：**
```
{Schema}://{Host}[:{Port}]/{BaseURI}/{ServiceURI}/{Version}/{Resource}[/{Child-Resource}]/{Action}
```

| 组成部分 | 说明 |
|----------|------|
| Schema | `HTTP` 或 `HTTPS`，推荐 `HTTPS` |
| BaseURI | 固定为 `openAPI` |
| ServiceURI | 服务/功能大类（见下表） |
| Version | `v1`、`v2`、`v3`… |
| Resource | 资源 |
| Child-Resource | 子资源 |
| Action | 动作 |

**URL 规则：**
- 全部使用**小驼峰**写法，只允许英文字母和数字
- 资源层级建议不超过 **3** 级
- 接口不向前兼容时需变更版本号（+1）

**ServiceURI 用词列表：**

| 子系统 | 服务名称 | ServiceURI |
|--------|----------|------------|
| 基础子系统 | 资源目录 | `resource` |
| 基础子系统 | 网关 | `gateway` |
| 基础子系统 | 设备接入 | `device` |
| 基础子系统 | 事件服务 | `event` |
| 基础子系统 | 系统配置 | `system` |
| 视频监控子系统 | 视频应用 | `video` |
| 门禁管理子系统 | 门禁管理 | `acs` |
| 访客管理子系统 | 访客管理 | `visitor` |
| 可视对讲子系统 | 可视对讲 | `vis` |
| 停车管理子系统 | 停车管理 | `parking` |
| 车辆卡口子系统 | 车辆卡口 | `vts` |
| 人员卡口子系统 | 人员卡口 | `pts` |
| 客流统计子系统 | 客流统计 | `cfs` |
| 梯控管理子系统 | 梯控管理 | `ecs` |
| 巡更管理子系统 | 巡更管理 | `sws` |
| 考勤管理子系统 | 考勤管理 | `tas` |
| 报警子系统 | 报警检测 | `as` |
| 运维子系统 | 系统运维 | `devOps` |

**Action 用词列表：**

| 动作 | 含义 |
|------|------|
| `add` | 添加 |
| `delete` | 删除 |
| `update` | 修改/更新 |
| `search` | 查询 |
| `get` | 获取 |
| `set` | 设置 |
| `on` | 开启 |
| `off` | 关闭 |
| `start` | 开始 |
| `stop` | 停止 |
| `invoke` | 触发/调用 |
| `upgrade` | 升级 |
| `import` | 导入 |
| `export` | 导出 |

**URL 示例：**
```
https://192.168.0.60/openAPI/resource/v1/organizations/add
https://192.168.0.60/openAPI/resource/v1/person/groups/delete
https://192.168.0.60/openAPI/resource/v1/persons/searchByTimeRange
https://192.168.0.60/openAPI/video/v1/camera/previewUrl/get
```

### 3.2 HTTP 方法

- **统一使用 `POST`** 方法

### 3.3 请求体

- 使用 **JSON** 格式
- 字段命名统一使用**小驼峰（lowerCamelCase）**风格
  - 示例：`deviceId`、`devicePtz`、`websocketUrl`、`serverIp`
- 枚举类型字段需在描述中列举取值及含义
- 时间/带单位字段需说明格式、单位及精度要求
- 可选字段需说明什么条件下携带
- 数组/列表类型字段命名增加 **"List"** 后缀（如 `deviceList`），不建议用 "s" 后缀
- 字段命名尽量与友商保持一致

### 3.4 响应体

- `code` 和 `message` 为**必带**字段
- `data` 为可选字段（无返回数据时可不返回）

**操作成功示例：**
```json
{
  "code": 0,
  "message": "Success."
}
```

**获取结果成功示例：**
```json
{
  "code": 0,
  "message": "Success.",
  "data": {
    "deviceIndexCode": "1000",
    "deviceName": "东门1-1"
  }
}
```

- 响应字段定义规则同请求字段

## 四、一致性

| 规则 | 说明 |
|------|------|
| 术语一致 | 接口命名涉及的术语保持一致，如 `deviceId` 不要写成 `devId`、`deviceID`、`devID` |
| 分页统一 | `pageNo`（从1开始）、`pageSize`、`total` 所有接口保持一致定义 |
| 顺序一致 | 接口参数、返回值定义顺序与示例顺序保持一致 |
| 类型一致 | 返回值类型必须与定义类型完全一致（string 不能返回 `null`，可返回空字符串 `""`） |
| 根节点 | 根节点 IndexCode 统一使用 `"1"`，父节点 IndexCode 统一使用 `"-1"`（禁止 `null`） |
| 布尔命名 | 逻辑变量字段**禁止**加 "is" 前缀（如用 `supportXXX` 或 `successFlag`，不用 `isSupportXXX`） |

**分页参数定义：**

| 参数名称 | 数据类型 | 是否必须 | 参数描述 |
|----------|----------|----------|----------|
| pageNo | integer | 是 | 当前页码，从1开始 |
| pageSize | integer | 是 | 分页大小 |
| total | integer | 否 | 记录总数 |

> 非分页接口无须提供上述字段。

**批量接口响应格式：**

有业务编码时：
```json
{
  "code": 0,
  "message": "Success.",
  "data": {
    "successList": [{ "indexCode": "499729383582334976" }],
    "failureList": [{ "indexCode": "499729383582334977", "code": 1000, "message": "Failed." }]
  }
}
```

无业务编码时（使用 `seqNo` 序号标识）：
```json
{
  "code": 0,
  "message": "Success.",
  "data": {
    "successList": [{ "seqNo": 1, "indexCode": "499729383582334976" }],
    "failureList": [{ "seqNo": 2, "code": 1000, "message": "Failed." }]
  }
}
```

## 五、安全

### 5.1 加密算法

**禁止**使用 DES、TDES、RC4 等不安全算法，应使用下表中的安全算法：

| 算法 | 密钥/哈希值长度（bit） | 其他要求 |
|------|----------------------|----------|
| AES | 128 / 192 / 256 | |
| ECDH/ECDHE | 256 / 384 / 512 | 安全曲线：curve25519 |
| ECDSA | 256 / 384 / 512 | 安全曲线：curve25519、secp256k1 |
| RSA | 2048 / 3072 / 4096 | |
| DSA | Prime P: 2048/3072/4096, Prime Q: 256/384/512 | |
| SM4 | 128 | |
| SHA | 256 / 384 / 512 | |

### 5.2 哈希算法

- 应使用 **256bit 以上**的安全 HASH 函数（如 SHA256、SHA512）
- **禁止**使用 MD5、SHA1

### 5.3 敏感信息

- 私钥、密码等关键安全参数及个人敏感信息必须使用额外的安全加密算法进行加密传输

### 5.4 传输要求

- 建议使用 **TLS 1.2+** 传输协议的安全加密套件
- 避免使用 HTTP 明文协议或含 SHA1、CBC 等弱加密套件
