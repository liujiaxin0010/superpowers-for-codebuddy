# 回填红线与自检

## 红线（禁止事项）

- 不写函数实现逻辑、条件分支、错误处理的细节
- 不罗列完整的 API 请求/响应字段，只写端点路径 + 用途
- 不写前端组件的 props/events/slots，只写组件职责和组合关系
- 不写数据库完整 schema，只写核心表名 + 关键字段和用途
- 不复述代码——如果读者需要看代码才能理解，引导他去看代码
- 不写已经过时的信息——代码已变，删除旧描述而非保留「历史版本」
- 不写与理解业务流程无关的技术细节

## 为什么有这些红线

文档的价值是「对齐语义」而非「规定语法」。复述代码的文档会随代码变化立即过时，且不能帮读者建立系统理解。Spec 聚焦「做什么」和「为什么」，具体实现路径由 AI 在 TDD 循环中自主决定。

## 回填自检清单

每次回填完成后核对：

- [ ] 流程图可渲染（Mermaid 语法正确，括号/箭头/角色名无破坏性字符）
- [ ] 功能完整性（覆盖所有用户可感知能力）
- [ ] 术语一致性（同一概念在不同文件用相同术语）
- [ ] 无实现细节泄漏（没有段落复述代码逻辑）
- [ ] 交叉引用有效（链接指向正确文件）
- [ ] 无过时信息（已删除的代码不再被描述为「存在」）
- [ ] 只改了 spec/（未动 CONTEXT.md / 源码）
