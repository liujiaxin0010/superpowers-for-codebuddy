# 架构升级反思

本文件只在同一个问题已经修了 3 次以上、仍然失败或引入新问题时读取。

## 什么时候强制触发

1. 同一 bug 的修复尝试失败 3 次以上
2. 每次修完都会在相邻路径引入新问题
3. 根因开始指向共享抽象、系统边界或设计缺陷

## 反思问题

1. 这是孤立 bug，还是系统性问题的表现？
2. 根因是否指向更深层的架构缺陷？
3. 继续修补症状，是否只会把问题推到别处？
4. 重构成本是否已经低于继续补丁的累积成本？

## 应向 Boss 报告什么

1. 已尝试了几次
2. 每次失败的方式
3. 当前最可能的架构层问题
4. “继续补丁”与“重构相关模块”的两种路径
5. 你的建议
