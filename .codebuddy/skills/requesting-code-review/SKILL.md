# 请求代码审查

本技能回答的是：**现在该不该审，应该审多深，发起前材料是否够。**

## 资源加载规则

当主表还不足以判断“这次应发起轻量 / 聚焦 / 完整 / 两阶段中的哪一种”时，必须读取：

- `references/review-depth-matrix.md`

当已经决定发起审查，需要整理正式的审查请求材料时，必须读取：

- `templates/review-request-template.md`

如果还停留在“要不要审”阶段，不要提前加载模板。

## 阻断条件

以下情况不要直接发起审查，返回 `BLOCKED` 或先补材料：

1. 审查范围不明确
2. 改动目的不明确
3. 没有任何验证证据或验证命令
4. 仍有未处理的严重问题或关键测试未通过
5. 需要的是“修复问题”而不是“先审查”

## 何时必须请求审查

| 场景 | 审查类型 | 必须？ |
|---|---|---|
| 子代理驱动开发中每个任务完成后 | 两阶段审查（spec-reviewer + code-reviewer） | **必须** |
| 重大功能实现后 | 完整代码审查 | **必须** |
| 合并到主干/main 之前 | 完整代码审查 | **必须** |
| Bug 修复后 | 聚焦审查（修复范围 + 回归） | **必须** |
| 重构后 | 聚焦审查（行为是否保持不变） | **建议** |
| 文档/配置更改 | 轻量审查 | **建议** |

## 深度选择协议

1. 子代理任务闭环默认两阶段，不得降级成一次普通审查
2. Bug 修复、本地重构、小范围回归优先聚焦审查
3. 功能完成、跨模块改动、主干合并前优先完整审查
4. 文档或配置小改动才考虑轻量审查
5. 遇到安全、权限、数据、迁移、共享契约风险时，只能升级，不能降级

## 审查前最小材料

至少要明确：

1. 审查范围
2. 改动目标
3. 相关文件或 diff
4. 已跑过的验证
5. 当前结论是否已达成
6. 希望 reviewer 重点关注的风险

缺少这些材料时，不要急着发起审查，先补上下文。

## 资源与边界

| 判断条件 | 加载技能 | 原因 |
|---|---|---|
| 审查涉及多语言通用规则 | `code-review-standards` | 提供语言级审查维度和规则 |
| 审查目标含 `.vue/.js/.ts` 前端代码 | `web-code-review` | 提供 Vue/TS 特化的缺陷分类和扫描流程 |
| 审查范围仅限”是否发起 + 深度 + 材料” | 本技能即可 | 不需要展开完整语言级审查 |

本技能负责”是否发起 + 用哪种审查 + 输出结构”，不负责展开完整的语言级审查规则。

## 输出要求

1. 若被阻断，明确缺什么材料、下一步该补什么
2. 若决定发起，必须说明审查类型、审查目标、已完成验证、重点风险
3. 正式请求时套用模板，避免口头化、即兴化发起

## 禁止事项

1. 不要在没有改动范围和验证信息时发起完整审查
2. 不要把子代理任务的两阶段审查降级成一次普通审查
3. 不要把“请求审查”和“开始自动修复”混成同一步
4. 不要遗漏审查类型、验证证据和重点风险
5. 不要在前端代码审查中忘记协同 `web-code-review`
