# 头脑风暴

通过结构化协作对话，在不写业务代码的前提下，把需求收敛成一份**可审阅、可交接、可进入计划阶段**的需求预分析文档。

## 核心约束

1. 只做需求澄清、方案比较、设计确认和文档生成，不写业务代码
2. 一次只推进一个阶段，不跨阶段并行追问
3. 一次一个问题，优先选择题，避免用多个开放问题淹没 Boss
4. 每个阶段结束前都要给出阶段小结，并等待 Boss 确认
5. 任何未确认信息都必须保留为待补充，不得擅自脑补

## 资源加载规则

### 阶段推进前

在开始阶段访谈前，**必须完整读取**：

- `references/stage-guide.md`

用途：

1. 明确每个阶段要收集什么
2. 明确每个阶段的结束条件
3. 复用建议提问方式，而不是在主文件里临场发挥

### 生成最终文档前

在写需求预分析文档前，**必须完整读取**：

- `requirement-doc-template.md`

用途：

1. 对齐最终章节结构
2. 保留模板中的填写引导
3. 对未收集信息保留 `<!-- TODO: 待补充 -->`

### 不要怎么加载

1. 不要一开始就直接生成整篇文档，先完成阶段访谈
2. 不要跳过 `stage-guide.md`，否则容易漏阶段或漏确认点

## 何时使用

以下情况优先使用本技能：

1. 需求边界不清，存在明显多种实现方向
2. 用户明确要“需求预分析文档/需求分析文档/按模板输出”
3. H 级任务需要系统化澄清和多轮确认
4. 需要形成完整的背景、组网、方案、设计、合规和兼容性说明

## 何时不用

以下情况优先考虑其他技能：

1. 需求已很清晰，只需轻量规格：优先 `spec-lite`
2. 用户明确要求直接做代码审查、修 bug、写测试：走对应专项技能
3. 用户只要一个简短方向建议，不需要完整文档：先走快速澄清，不强制展开全流程

## 七阶段工作流

1. **背景与需求功能点**：收敛"到底要解决什么问题"，而不是"想要什么功能"——功能是手段不是目标
2. **应用组网与竞品分析**：明确系统边界（谁调用谁、数据从哪来到哪去），避免后续设计时遗漏上下游依赖
3. **技术分析与方案选型**：至少给出 2-3 个可对比方案，每个方案列出优劣和适用条件——单一方案等于没有选择
4. **软件设计分段确认**：核心接口、数据模型、关键流程逐项确认，每项都要 Boss 签字——未确认的设计在实现时会被反复推翻
5. **检查清单与合规**：安全/权限/合规不是事后补，是设计阶段就要识别的硬约束
6. **跨模块与兼容性分析**：新功能对现有模块的影响，向前兼容和向后兼容的约束
7. **收尾评估与文档生成**：生成严格匹配模板的需求预分析文档

## 阶段推进协议

对每个阶段都按以下顺序执行：

1. 从 `references/stage-guide.md` 读取当前阶段要求
2. 用 1 个短问题推进当前阶段
3. 收到信息后给出阶段小结
4. 明确“已确认 / 待补充 / 不适用”
5. 只有在 Boss 确认后，才进入下一阶段

## 输出契约

最终输出必须：

1. 严格匹配 `requirement-doc-template.md`
2. 保存到 `docs/plans/YYYY-MM-DD-<需求名称>-需求预分析.md`
3. 所有图表统一使用 Mermaid
4. 所有未确认项保留标题并标记 `<!-- TODO: 待补充 -->`
5. 完成后向 Boss 展示完整文档并获取最终确认

## 质量标准

一份合格的需求预分析文档至少满足：

1. 需求目标、范围、优先级明确
2. 至少有 2-3 个可对比的技术方案或明确说明为何无需比较
3. 核心接口、流程、数据或界面中至少一类有设计说明
4. 安全/合规/兼容性不缺章节
5. 所有待补充信息都被显式标注，而不是静默遗漏

## 禁止事项

1. 不要跳过阶段，即使 Boss 说”简单做做”——跳阶段会导致后续章节缺少输入，最终文档返工；Boss 说”简单”往往是因为还没想到复杂的部分
2. 不要一次提很多问题——多问题并发会让 Boss 选择性忽略关键项，且回复质量与问题数量负相关
3. 不要把未确认内容写成既定事实——未确认的假设一旦进入文档会被下游当作已批准基线，纠正成本随传播距离指数增长
4. 不要生成非 Mermaid 图表——非 Mermaid 图表无法在 Markdown 渲染环境中正确显示和版本追踪
5. 不要在文档完成前切换到实现相关技能——未收敛的需求进入实现会导致大面积返工
6. 不要用开放问题代替选择题——“你觉得怎么做好？”让 Boss 从零思考，而”方案 A 还是方案 B？”让 Boss 做判断，后者效率高一个数量级

## 下一步

头脑风暴通过后，默认下一步是**编写实施计划**；若 Boss 要求继续收敛轻量规格，可回到 `spec-lite` 补追踪链接。
