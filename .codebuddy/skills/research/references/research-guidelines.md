# 工程研究指南

## 研究判断框架

在下结论前，至少问自己：

1. 这条结论是**事实**还是**推断**
2. 它是否已经有直接证据支撑
3. 它对后续 spec / plan / execute 有什么影响
4. 它是否需要被写入 `findings.md` 复用

## 三类结论区分

- **事实**：能直接从代码、配置、目录、命令输出中验证
- **推断**：基于事实归纳出的判断，必须写清依据；若写成事实，会被下游 spec/plan 当作已批准基线，导致设计建立在未经验证的假设上
- **未知项**：当前证据不足，必须由用户确认或后续补充；若跳过，会被执行者自行填充，产生无法追溯的需求偏移

## 研究结束条件

满足以下条件时，研究可结束并交给下游：

1. 已明确研究范围和未覆盖边界
2. 已给出足够支持下游决策的事实
3. 推断都带有依据
4. 未知项已被显式列出
5. 下一步建议明确：继续 research / 写 spec / 请求确认
