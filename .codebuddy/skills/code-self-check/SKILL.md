# 代码自检

用于在提交前执行统一代码自检，支持 Git 与 SVN。默认只输出问题与修复建议，不直接改代码。

## 输入参数

- `vcs=auto|git|svn`
- `diffPath=<path>`（可选，优先使用已有 diff/patch）
- `applyFix=true|false`（可选，默认 false）

## 阻断条件

以下任一情况返回 `BLOCKED`：

1. 无法确定版本控制类型
2. `diffPath` 指向的文件不存在
3. 没有可审查的 diff/patch 内容

## VCS 检测

1. `vcs=git`：固定使用 `git diff`
2. `vcs=svn`：固定使用 `svn diff`
3. `vcs=auto`：
   - 存在 `.git` 则走 Git
   - 否则存在 `.svn` 则走 SVN
   - 否则返回 `BLOCKED`

## 审查范围

1. 优先审查新增/修改行（diff 中 `+` 语句）
2. 必要时阅读相邻上下文，确认影响范围
3. 若问题明显超出 diff 范围，只记录风险，不擅自扩展修复范围

## 审查维度

至少按以下维度检查：

1. **正确性**：空值、边界、条件遗漏、错误返回、状态不一致
2. **安全性**：输入校验、权限、敏感信息、注入风险
3. **回归风险**：改动是否破坏已有调用方、契约、日志或配置
4. **测试与验证**：是否补了必要测试，验证命令是否覆盖主路径
5. **可维护性**：重复代码、命名歧义、过度复杂、无证据的兼容代码

## 严重度定义

- **高**：功能错误、安全问题、数据风险、明显回归风险，必须修复
- **中**：可维护性问题、测试缺口、边界遗漏，建议本轮修复
- **低**：低风险改进项或可选优化，不阻断提交

## applyFix 边界

`applyFix=true` 时，只允许修复以下内容：

1. 已在自检报告中明确列出的问题
2. 位于 diff 行或其直接相邻上下文中的问题
3. 可以通过现有验证命令快速确认的修复

以下情况**不得自动修复**，只能输出报告：

1. 需要重构多个模块
2. 需要修改共享契约或公共接口
3. 需要用户确认方向
4. 只有风格意见、没有明确缺陷证据

## 输出要求

报告输出到：`docs/quality/code-self-check-report.md`

每条问题至少包含：

1. 严重度
2. 文件位置
3. 问题描述
4. 证据或触发原因
5. 修复建议
6. 是否适合 `applyFix`

## 推荐输出格式

```markdown
# 代码自检报告

## 高
1. `src/...:12`
   - 问题：
   - 证据：
   - 建议修复：

## 中
...

## 低
...
```

## 禁止事项

1. 不要用“全仓扫描”代替 diff 自检
2. 不要在没有位置和证据时给出空泛问题
3. 不要把风格建议和功能缺陷混成同一优先级
4. 不要在 `applyFix=true` 时顺手扩大修复范围
5. 不要未跑验证就标记“已修复”
