# 代码自检

本技能用于回答更具体的问题：**当前这份 diff 有什么问题、严重度是什么、哪些可以自动修、哪些只能报告。**

## 输入参数

- `vcs=auto|git|svn`
- `diffPath=<path>`（可选，优先使用已有 diff/patch）
- `applyFix=true|false`（可选，默认 `false`）

## 资源加载规则

当需要判断“这份 diff 属于哪种审查场景、严重度应侧重什么、`applyFix` 是否安全”时，再读取：

- `references/diff-scenarios.md`

当需要输出正式的自检报告时，再读取：

- `templates/code-self-check-report-template.md`

不要一开始就把整份场景矩阵读入上下文；先确认当前 diff 的类型，再按需读取。

## 何时使用

1. 提交代码前需要对当前 diff 做结构化审查
2. 已有 patch 文件需要审查其中的问题和风险
3. 用户显式调用 `/self-check` 或提到"自检/diff 审查/提交前检查"
4. 需要在低风险前提下选择性自动修复 diff 中的问题

## 何时不用

1. 需要的是完整代码审查而非 diff 自检——应使用 `requesting-code-review`
2. 没有任何未提交的改动或 diff 内容
3. 需要全仓扫描或架构级审查——超出本技能范围
4. 改动已通过审查并合入，事后复盘不适用 diff 自检

## 阻断条件

以下任一情况返回 `BLOCKED`：

1. 无法确定版本控制类型
2. `diffPath` 指向的文件不存在
3. 没有可审查的 diff/patch 内容

## VCS 检测

1. `vcs=git`：固定使用 `git diff`
2. `vcs=svn`：固定使用 `svn diff`
3. `vcs=auto`：
   - 存在 `.git` 则走 Git
   - 否则存在 `.svn` 则走 SVN
   - 否则返回 `BLOCKED`

## 审查范围

1. 优先审查新增/修改行（diff 中 `+` 语句）
2. 必要时阅读相邻上下文，确认影响范围
3. 若问题明显超出 diff 范围，只记录风险，不擅自扩展修复范围

## 决策协议

1. 先识别 diff 类型：业务逻辑 / 测试 / 配置脚本 / 文档注释 / 共享契约
2. 再按场景挑重点：正确性、安全性、回归风险、测试与验证、可维护性
3. 再决定严重度：高 / 中 / 低
4. 最后决定 `applyFix`：只在低风险、边界清晰、现有验证足够时允许

## 严重度定义

- **高**：功能错误、安全问题、数据风险、明显回归风险，必须修复
- **中**：可维护性问题、测试缺口、边界遗漏，建议本轮修复
- **低**：低风险改进项或可选优化，不阻断提交

## `applyFix` 风险边界

### 允许自动修复

`applyFix=true` 时，只允许修复以下内容：

1. 已在自检报告中明确列出的问题
2. 位于 diff 行或其直接相邻上下文中的问题
3. 可以通过现有验证命令快速确认的修复
4. 不会扩大到共享契约或跨模块改动的修复

### 禁止自动修复

以下情况**不得自动修复**，只能输出报告：

1. 需要重构多个模块
2. 需要修改共享契约或公共接口
3. 需要用户确认方向
4. 只有风格意见、没有明确缺陷证据
5. 现有验证命令不足以证明修复安全

## 输出要求

报告输出到：`docs/quality/code-self-check-report.md`，每条问题至少包含：

1. 严重度
2. 文件位置
3. 问题描述
4. 证据或触发原因
5. 修复建议
6. 是否适合 `applyFix`

如果执行了 `applyFix=true`，还要补充：

1. 实际应用了哪些修复
2. 重新跑了什么验证
3. 是否还有剩余风险

## 禁止事项

1. 不要用“全仓扫描”代替 diff 自检
2. 不要在没有位置和证据时给出空泛问题
3. 不要把风格建议和功能缺陷混成同一优先级
4. 不要在 `applyFix=true` 时顺手扩大修复范围
5. 不要未跑验证就标记“已修复”
