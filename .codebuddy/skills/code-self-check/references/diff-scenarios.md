# Diff 审查场景矩阵

本文件只在需要判断 diff 类型、`applyFix` 风险和审查重点时读取。

## 场景一：业务逻辑改动

### 关注重点

1. 条件遗漏、边界遗漏、错误返回
2. 共享契约影响
3. 回归测试是否覆盖主路径

### `applyFix` 建议

- 仅当修复局限在当前 diff 附近，且验证命令足够时才允许

## 场景二：测试改动

### 关注重点

1. 是否测试行为而不是实现细节
2. 是否引入脆弱断言
3. 是否遗漏失败路径和边界条件

### `applyFix` 建议

- 默认只修明显错误，不自动重写整组测试

## 场景三：配置/脚本改动

### 关注重点

1. 默认值是否安全
2. 环境差异是否被考虑
3. 是否影响启动、部署、权限

### `applyFix` 建议

- 只有在风险很低、验证明确时才允许

## 场景四：共享契约改动

### 关注重点

1. 调用方是否同步
2. 是否影响序列化/反序列化
3. 是否影响测试和文档

### `applyFix` 建议

- 默认禁止自动修复，只输出报告

## 快速判定

如果你无法在 30 秒内判断这份 diff 是否会影响共享契约，就把它先当作“共享契约改动”处理。
