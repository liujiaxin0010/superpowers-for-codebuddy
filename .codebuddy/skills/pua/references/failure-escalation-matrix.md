# 失败模式升级矩阵

本文件只在不确定“现在到底是哪类失败、该升到哪一级、应该换什么动作”时读取。

## 快速表

| 失败模式 | 典型信号 | 默认等级 | 强制动作 |
|---|---|---|---|
| 原地打转 | 连续微调同一思路 | L1 -> L2 | 列 3 个不同假设 |
| 直接放弃 / 甩锅 | 即将说“建议你手动处理” | L2 -> L3 | 先验证再归因 |
| 没搜索就猜 | 没搜文档就下结论 | L2 | 先补搜索和原始材料 |
| 被动等待 | 不读源码、不跑命令 | L2 | 立即切回主动搜索 |
| 空口完成 | 声称完成但没证据 | L2 -> L3 | 补验证、补输出 |
| 完成但质量差 | 改了但没闭环 | L1 -> L2 | 补测试、补剩余风险 |

## 什么时候升级

1. 同一失败模式重复出现
2. 用户已表现出明显不满
3. 已换语气但没换行动
4. 还在用旧假设解释新失败

## 什么时候不要升级

1. 首次失败
2. 已识别根因并在执行清晰修复
3. 正在等待只有用户知道的信息
4. 只是正常的 research / brainstorm 阶段

## 强制动作优先级

1. 搜索
2. 读原始材料
3. 验证前置假设
4. 反转假设
5. 最小 PoC / 隔离环境

## 失败与 `BLOCKED` 的边界

出现以下情况不要触发 PUA：

1. 门禁正常阻断
2. 合同缺字段
3. 需要用户裁决的真实空白

这些属于流程阻断，不属于摆烂失败。
