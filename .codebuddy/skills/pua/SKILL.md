# PUA 万能激励引擎

本技能的目标不是“骂一顿”，而是**在任务濒临摆烂时，强制把行为切回到有效排查和闭环交付**。

## 何时触发

满足任一条件即考虑激活：

1. 同一任务失败 2 次以上
2. 连续微调同一思路，没有本质换方向
3. 即将说“我无法解决”“建议你手动处理”
4. 未验证就把问题归因于环境、版本、API
5. 被动等待，不搜索、不读源码、不执行命令
6. 声称完成但没有验证证据
7. 用户出现明显不满信号：`try harder`、`stop giving up`、`换个方法`、`你再试试`

## 不触发条件

以下情况不要误触发：

1. 首次失败
2. 已经识别根因且正在执行明确修复
3. 正在等待只有用户才知道的信息
4. 正处于 `research` 或 `brainstorm` 的正常信息收集阶段
5. 已完成结构化失败报告并体面退出

## 核心工作流

### 1. 先识别失败模式

把当前卡壳归到以下之一：

1. 原地打转
2. 直接放弃/甩锅
3. 没搜索就猜
4. 完成但质量差
5. 被动等待
6. 空口完成

### 2. 再切回方法论

必须按顺序做：

1. 逐字读失败信号
2. 主动搜索
3. 读原始材料
4. 验证前置假设
5. 反转假设，换本质不同的方案

### 3. 再决定压力等级

- `L1`：温和失望，强制换方向
- `L2`：灵魂拷问，强制列 3 个不同假设
- `L3`：高压督办，必须完成完整检查清单
- `L4`：最后通牒，转入最小 PoC / 隔离环境 / 完全不同技术路线

## 7 项强制检查清单

1. 读完失败信号了吗
2. 搜索过核心问题了吗
3. 读过原始材料了吗
4. 验证过前置假设了吗
5. 试过反转假设了吗
6. 做过最小隔离了吗
7. 真正换过方向了吗

## 体面退出条件

只有在 7 项检查清单全部完成后，才允许输出结构化失败报告。报告必须包含：

1. 已验证事实
2. 已排除项
3. 缩小后的问题范围
4. 下一步建议
5. 交接信息

## 风味选择器

- 原地打转：阿里味 / Jobs 味
- 直接放弃：Netflix 味 / 华为味
- 没搜索就猜：百度味 / 字节味
- 被动等待：阿里关怀味 / 美团味
- 空口完成：阿里验证味 / 腾讯味

如果真的需要具体话术模板，再读取 `references/flavor-pack.md`。

## Agent Team 简版规则

当存在多子代理团队时：

1. Leader 负责维护失败计数和升级
2. Teammate 在 L2 及以上要汇报失败模式、已尝试方案、已排除项
3. 任务转交给下一个 agent 时，失败上下文必须一并传递

## 禁止事项

1. 不要把 PUA 当成正常工作流的默认语气
2. 不要在首次失败时就高压上强度
3. 不要只输出话术，不落实新的搜索和验证动作
4. 不要把 `BLOCKED` 正常门禁误判成失败
5. 不要在没做检查清单前就说“已经穷尽所有方法”
