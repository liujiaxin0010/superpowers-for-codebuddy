# Worktree 边界案例

本文件只在遇到复用、残留、冲突或清理失败时读取。

## 场景一：同名分支已存在

先判断：

1. 是否已被另一个 worktree 检出
2. 是否就是当前任务的历史 worktree
3. 是否应该改用新分支名

若分支已被其他 worktree 使用，默认不要复用。

## 场景二：目录已存在但不是有效 worktree

可能是：

1. 历史残留目录
2. 手动创建的普通目录
3. 上次失败留下的半成品

做法：

1. 先确认目录来源
2. 再决定清理、复用或改名

## 场景三：清理失败

优先检查：

1. 未提交改动
2. 进程占用
3. 是否尚未 merge / push / stash

不要先上 `--force`，除非 Boss 已确认放弃。

## 场景四：多个代理都想用同一 worktree

默认禁止。一个 worktree 只属于一个明确任务或一个明确代理。
