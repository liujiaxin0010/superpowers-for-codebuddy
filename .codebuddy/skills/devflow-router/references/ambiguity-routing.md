# 模糊需求路由参考

本文件只在路由时无法判断“要不要先走 `/brainstorm`”时读取。

## 文档产物意图优先

如果用户明确要求以下任一文档形态，优先走 `/brainstorm`：

1. 需求预分析文档
2. 需求分析文档
3. 按头脑风暴模板输出
4. 按 requirement-doc-template 生成

## `must-brainstorm`

满足任意一条即可归为必须先 `/brainstorm`：

1. 只有目标，没有范围边界
2. 只有一句“帮我做这个/加这个”，没有用户、场景、入口或验收标准
3. 存在多个实现方向，但用户尚未选方向
4. 需求可能跨模块，但没有说明影响范围
5. 需求包含“优化一下/改造一下/升级一下”这类宽泛表述，且未定义行为边界

## `should-brainstorm`

满足任意一条即可归为建议先 `/brainstorm`：

1. 已有明确目标，但验收标准仍偏粗
2. 已知大致范围，但用户/场景/入口不完整
3. 主要影响单模块，但边界条件仍未定义
4. 已有倾向方案，但仍缺少用户确认

## 输出动作

### 对 `must-brainstorm`

1. `recommendedCommand=/brainstorm`
2. 明确写出边界不清或方向未定
3. 不替用户猜范围

### 对 `should-brainstorm`

1. 默认仍推荐 `/brainstorm`
2. 若用户坚持快速收敛且最小字段齐备，可退到 `/spec-lite`
