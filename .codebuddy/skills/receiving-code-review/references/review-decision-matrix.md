# Review 结论矩阵

本文件只在你不能立刻决定“同意 / 部分同意 / 不同意 / 暂不确定”时读取。

## 同意

适用：

1. 你已经复现或能清楚证明问题成立
2. 修复方向与当前边界一致
3. 验证成本可控

应输出：

1. 问题为什么成立
2. 你修了什么
3. 用什么证据证明已闭环

## 部分同意

适用：

1. 问题真实存在，但 reviewer 给的修法不是最优
2. 你同意目标，不同意实现手段
3. 你能给出更低风险或更贴边界的替代方案

应输出：

1. 哪一部分同意
2. 为什么不直接按建议改
3. 你的替代动作和验证证据

## 不同意

适用：

1. 现有行为有明确契约或上游约束支撑
2. 你已经验证 reviewer 的判断不成立
3. 直接按建议改会引入更高风险或越界

应输出：

1. 为什么不同意
2. 你的证据来自哪类验证
3. 是否需要 Boss / owner 裁决

不要做的事：

1. 只说“我觉得没问题”
2. 没复现就直接反驳高严重度意见

## 暂不确定

适用：

1. 证据不够
2. 问题涉及方向性权衡
3. 当前无法在合理成本内复现或证伪

应输出：

1. 还缺什么证据
2. 谁需要裁决
3. 你建议的下一步

## 证据类型优先级

优先使用：

1. 可复现用例 / 测试
2. 基准或实际运行结果
3. 共享契约、接口定义、数据模型
4. 代码走读与控制流推理

弱证据：

1. “看起来像”
2. “我习惯这样写”
3. “大概不会出问题”

## 高风险评论的默认动作

出现以下任一情况时，不要直接进入“不同意”：

1. 安全
2. 权限
3. 数据一致性
4. 删除 / 迁移 / 回滚
5. 共享契约破坏

先补复现、契约或 owner 裁决证据。
