# 计划拆解指南

## 拆解决策矩阵

| 任务特征 | 拆解方式 |
|---|---|
| 共享契约、共享配置、数据模型变更 | 单独成任务，且优先于消费方修改 |
| 独立实现、独立验证、边界清晰 | 可单列为实现任务 |
| 多模块接入、回归、文档同步 | 作为集成/收尾任务单列 |
| 高风险迁移或回滚 | 单独成任务，且必须带验证命令 |

## 任务拆解启发式

### 1. 先拆共享边界

以下内容优先单独成任务：

1. 接口契约
2. 数据模型/协议
3. 公共组件或公共配置
4. 迁移、回滚准备、权限变更

### 2. 再拆独立实现

独立实现任务应满足：

1. 允许修改范围明确
2. 有独立验证命令
3. 不依赖未完成的共享边界

### 3. 最后拆集成与收尾

集成类任务必须单列，不要混入实现任务中：

1. 接入现有系统
2. 回归验证
3. 代码审查
4. 文档同步

## 依赖与并行规则

### 必须串行

1. 共享契约变更在前，消费方修改在后
2. 数据迁移准备在前，真实切换在后
3. 高风险集成在前，全面回归在后

### 可以并行

只有同时满足以下条件才可并行：

1. 不共享核心文件或共享契约
2. 不依赖对方输出
3. 验证命令可独立运行
4. owner 清晰
