# 完成开发分支

当实现已完成、局部验证已通过时，统一做一次**可交付前的收尾检查**，而不是边做边口头宣布“差不多了”。

## 何时使用

以下条件都满足时使用本技能：

1. 计划中的任务已完成
2. 局部验证已通过
3. 代码审查已完成，或准备进入最后一次全局审查

## 阻断条件

出现以下任一情况时，返回 `BLOCKED`：

1. 关键测试未通过
2. 仍有未解释的本地改动
3. 仍存在未处理的严重审查问题
4. 用户尚未确认最终收尾路径

## 收尾工作流

### 1. 最终验证

至少完成：

1. 运行完整测试套件
2. 检查未提交的更改
3. 检查遗留调试代码、TODO/FIXME/HACK
4. 确认三层代码自文档已更新

### 2. 代码清理

重点清理：

1. 调试日志和临时输出
2. 注释掉的代码块
3. 临时开关、临时脚本、临时 mock

### 3. 全局代码审查

若任务由多个子任务组成，或使用过子代理开发，必须做一次整体视角审查：

1. 模块之间是否正确集成
2. 是否引入重复实现或风格割裂
3. 是否存在遗漏的收尾文档和风险说明

### 4. 选择收尾路径

向 Boss 展示四种收尾路径：

- `A`：创建 PR/MR
- `B`：合并到主干
- `C`：保留分支
- `D`：放弃分支

## 收尾路径选择矩阵

| 条件 | 推荐路径 |
|---|---|
| 团队协作、需要他人审查 | `A: 创建 PR/MR` |
| 个人项目、验证充分、准备直接收口 | `B: 合并到主干` |
| 功能已完成但仍需观察或等待业务确认 | `C: 保留分支` |
| 实验失败、方向放弃、确认不再保留成果 | `D: 放弃分支` |

## 危险操作规则

以下操作必须在 Boss 明确确认后执行：

1. 删除分支
2. 强制删除 worktree
3. 直接合并到主干

## 收尾前最后一问

真正执行收尾路径前，必须再确认：

1. 当前结果是否已经具备交付证据
2. 是否仍存在未解释风险
3. 这个分支是否需要保留作为回滚点、对比点或后续继续开发点

## Git 最小示例

```bash
git push -u origin feature/功能描述
gh pr create --title "功能描述" --body "详细说明"
```

```bash
git checkout main
git merge feature/功能描述
git push
```

## Worktree 清理

如果使用过 worktree，收尾时必须确认：

1. 任务已合并或已明确放弃
2. worktree 中无未保存成果
3. 清理后 `git worktree list` 结果符合预期

## SVN 最小示例

```bash
SVN_ROOT=$(svn info --show-item repos-root-url)
svn switch "$SVN_ROOT/trunk"
svn merge "$SVN_ROOT/branches/feature-功能描述"
svn commit -m "merge: 合并功能分支 功能描述"
```

## 完成定义

只有以下条件都满足，才算真正收尾完成：

1. 测试通过并展示了证据
2. 本地改动状态清楚
3. 调试代码已清理
4. 文档已同步
5. Boss 已确认最终操作路径
6. 选定路径已执行并反馈结果

## 禁止事项

1. 不要在测试未通过时开始收尾
2. 不要把“创建 PR”和“直接合并”混成默认同一步
3. 不要在未确认时删除分支或强制清理 worktree
4. 不要遗漏全局视角的回归检查
5. 不要只说“已完成”却不给验证证据
