# 测试规则冲突示例

本文件只在规则冲突或多风格共存时读取。

## 场景一：仓库里同时有 Jest 和 Vitest

处理顺序：

1. 看目标模块附近主要用哪个
2. 看是否有显式 `external_test_rules`
3. 若仍冲突，返回 `BLOCKED`

## 场景二：仓库里多数文件用 `tests/`，但当前模块用 `__tests__/`

优先跟随当前目标模块附近风格，不要因为“全仓更多”就覆盖局部惯例。

## 场景三：规则文件要求不 mock 数据库，但现有测试都 mock 数据库

显式规则优先，但要在输出中说明：

1. 采用了规则文件要求
2. 与现有测试风格存在偏差
3. 后续应统一项目策略
