# GitLab CE 14.8.2 CI/CD 配置适配基线

本文件是 Featureflow 所有 CI/CD 产物（`/ci-setup` 生成的 `.gitlab-ci.yml`、定时配置、Phase D 的 ci-principles 增强）的**版本适配基线**。目标平台：内网自建 **GitLab Community Edition 14.8.2**（2022-02 发布）。

> 原则：**安全子集**。只用 14.8 已稳定的 YAML 关键字与配置；凡 14.8 之后才引入的特性一律不用。这样即便个别边界判断有偏差，生成的流水线也必然能在 14.8.2 上跑。
>
> 若本实例实测与本文不符，以该 GitLab 的 **CI Lint 页面**（`项目 → CI/CD → 编辑器 / CI Lint`）与官方文档为准——同 `gitlab-bridge` 的「预期映射，实测修正」策略。

## 1. 强门禁载体（CE 的根本约束）

CE 缺失 EE 的 Push Rules、MR Approval Rules、Security/SAST widget。**CE 14.8.2 唯一可靠的「阻断合并」机制**：

| 机制 | 位置 | 作用 |
|---|---|---|
| Pipelines must succeed | Settings → Merge requests | 流水线红 → MR 合不了（核心硬门禁载体）|
| All threads must be resolved | Settings → Merge requests | 未解决讨论 → 合不了 |
| Protected Branches | Settings → Repository | master「Allowed to merge: Maintainers」「Allowed to push: No one」|

结论：**所有想强制的门禁，统统做成 `.gitlab-ci.yml` 的 job**。一个 pipeline 收口全部强门禁。

## 2. 可用 YAML 关键字（14.8 安全子集）

| 类别 | 关键字 | 备注 |
|---|---|---|
| 结构 | `stages`、`default:`（image/before_script 等）、`variables`、`workflow:rules` | ✅ |
| 触发规则 | `rules:` + `if` / `changes` / `exists`、`only`/`except`（旧式，建议用 rules）| ✅ |
| 依赖编排 | `needs:`（DAG）、`dependencies:`、`stage:` | needs 自 12.2 ✅ |
| 并行 | `parallel:`、`parallel:matrix:` | matrix 自 13.3 ✅ |
| 真集成 | `services:`（postgres/redis/rabbitmq 等）| ✅ e2e 真实中间件 |
| 产物 | `artifacts:` + `paths` / `when`(always/on_failure/on_success) / `expire_in` / `reports:junit` / `reports:coverage_report` | ✅ |
| 覆盖率 | `coverage:`（job 级正则）+ `artifacts:reports:coverage_report:coverage_format: cobertura` | ✅ 见 §4 |
| 复用 | `extends:`、`include:`(local/file/remote/template)、`!reference` | !reference 自 13.0 ✅ |
| 控制 | `when:`(manual/delayed/always/on_failure)、`allow_failure`、`retry`、`timeout`、`interruptible`、`resource_group` | ✅ |
| 缓存 | `cache:`（key/paths/policy）| ✅ |
| 环境 | `environment:`、`rules` 配合手动部署 | ✅ |

可用触发变量：`$CI_PIPELINE_SOURCE`（取值含 `push` / `merge_request_event` / `schedule` / `web` / `api` / `pipeline`）、`$CI_MERGE_REQUEST_*`、`$CI_COMMIT_*`、`$CI_JOB_ID`、`$CI_PROJECT_*`。

## 3. 禁止使用（14.8 之后引入 / EE-only）

| 关键字 / 功能 | 引入版本 | 处理 |
|---|---|---|
| `id_tokens`（OIDC ID 令牌）| 16.4 | ❌ 不用；密钥走 CI Variables（masked/protected）|
| `spec:inputs` / `include:inputs`（CI inputs）| 17.x | ❌ 不用；参数化用 `variables` + `rules` |
| CI/CD components / catalog（`include:component`）| 17.0 | ❌ 不用；复用走 `include:local/remote` + `extends` |
| `run:` steps 关键字 | 17.x | ❌ 不用；用 `script` |
| `manual_confirmation` | 17.x | ❌ 不用；手动 job 用 `when: manual` |
| Merge Trains | EE | ❌ 不依赖 |
| MR Approval Rules 强制（N 人审批）| EE | ❌ 用 Protected Branches + MR 模板 checklist 替代 |
| Push Rules（commit 规范强制）| EE | ❌ 用 `verify:commit-msg` job 替代 |
| SAST / DAST / Secret Detection widget | Ultimate | ❌ P0 不做；后续可在 CI 自带开源工具产出 artifact，但无 MR widget |

> Code Quality（codeclimate）模板技术上 CE 可跑（需 Docker-in-Docker runner，产出 `artifacts:reports:codequality`），但本基线 P0 不启用，避免对 runner 形态的强假设。

## 4. 覆盖率配置（CE 14.8.2 正确写法）

14.0 起 `artifacts:reports:cobertura` 已被 `coverage_report` 取代。14.8 正确写法：

```yaml
test:unit:
  stage: test
  script:
    - <测试命令，产出 cobertura xml 与 junit xml>
  coverage: '/^TOTAL.+?(\d+\.\d+%)$/'   # job 级正则提取覆盖率数字（替代 15.0 移除的项目级设置）
  artifacts:
    when: always
    reports:
      junit: report.xml
      coverage_report:
        coverage_format: cobertura
        path: coverage/cobertura-coverage.xml
    expire_in: 30 days
```

要点：
- 用 **job 级 `coverage:` 正则**，不要依赖「Settings → CI/CD → Test coverage parsing」项目级正则（15.0 已移除，前向不兼容）
- `coverage_format` 仅 `cobertura` / `jacoco`；其它语言需转换为 cobertura 格式
- `reports:` 文件**始终上传**（`when: always`），失败 job 也能从 artifact 诊断

## 5. e2e 真实中间件（services）

L3 系统测试需真实依赖时，用 `services:`（CE 14.8.2 完整支持）：

```yaml
e2e-test:
  stage: e2e
  services:
    - name: postgres:15
      alias: postgres
    - name: redis:7
      alias: redis
  variables:
    POSTGRES_DB: testdb
    DB_HOST: postgres
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
    - if: '$CI_PIPELINE_SOURCE == "schedule"'
```

并行 e2e job 必须**资源隔离**：用 `$CI_JOB_ID % 100` 做端口偏移与 Compose 项目名隔离，避免端口冲突的间歇性失败。

## 6. 定时流水线（CE 14.8.2 原生 Pipeline Schedules）

CE 14.8.2 原生支持 **Pipeline Schedules**（`项目 → CI/CD → 计划`，cron 语法）。配合 `rules` 区分定时与 MR：

```yaml
nightly-review:
  rules:
    - if: '$CI_PIPELINE_SOURCE == "schedule"'
```

这是 `scheduled-automation` 的 **GitLab 原生触发选项**：调度由 GitLab 计划触发，agent 任务在 runner 上由 `codebuddy` CLI 执行。纯 CI 类定时（如覆盖率全量）可直接用 schedule job；AI 驱动类（审查/修复/发布）需 runner 能拉起 CLI。

## 7. EE → CE 取舍总表

| EE/Ultimate 功能 | CE 14.8.2 替代 |
|---|---|
| Push Rules | CI job `verify:commit-msg` |
| MR Approval Rules（强制审批）| Protected Branches「Maintainers only」+ MR 模板 checklist |
| SAST / DAST / Secret Detection widget | 不做；可选 CI 内开源工具产 artifact |
| Code Quality widget | P0 不做（需 DinD）|
| Merge Trains | 不依赖；串行合并 + 合并前 rebase |
| `id_tokens` OIDC | CI Variables（masked + protected）|

## 8. 适配自检清单

生成 / 修改任何 `.gitlab-ci.yml` 后核对：

- [ ] 无 `id_tokens` / `spec:inputs` / `include:component` / `run:` steps 等 14.8 后特性
- [ ] 覆盖率用 job 级 `coverage:` 正则 + `coverage_report:cobertura`，未依赖项目级 regex 设置
- [ ] `artifacts:reports:` 配 `when: always`
- [ ] 强门禁项都是 pipeline job（不假设 Push/Approval Rules 可用）
- [ ] 定时 job 用 `$CI_PIPELINE_SOURCE == "schedule"` 区分
- [ ] 经 `gitlab-bridge` 的 `ci.lint`（或人工 CI Lint 页面）校验语法通过
