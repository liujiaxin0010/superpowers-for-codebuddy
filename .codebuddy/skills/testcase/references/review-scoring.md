# 测试用例评审：五维加权评分

测试用例设计完成后做评审，用五维加权评分量化质量，多轮迭代深化。

## 五维加权评分体系

| 维度 | 权重 | 评什么 |
|---|---|---|
| 功能覆盖 | 25% | 是否覆盖所有功能点，有无遗漏模块/接口 |
| 流程覆盖 | 20% | 是否覆盖核心业务链路，特别是跨模块端到端流程 |
| 脱离实现 | 15% | 用例是否验证行为而非绑定实现细节 |
| 饱和覆盖 | 25% | 正常 + 异常 + 边界场景是否均有用例 |
| 引用准确性 | 15% | 用例是否与设计文档、需求文档保持一致 |
| **合计** | **100%** | |

## 评审流程

1. 按五维打分，算加权总分
2. 识别缺口，列出改进建议
3. 每轮补充后重新评分，直到各维度达标
4. 用「N 维度 × M 测试套」矩阵分析发现覆盖缺口并逐项修复

## 用例 ↔ 代码双向映射

建立测试用例文档与测试函数的双向映射，量化追溯关系：

- **正向映射**：测试用例文档 → 测试函数（已映射 / 部分映射 / 未映射 比例）
- **反向映射**：测试函数 → 测试用例（含置信度标注：高/中/低）
- 用例括号中标注对应测试函数名（如 `TC-SEARCH-001, TestQuery_ByID_Success`）

## 评审维度（定性）

- 功能覆盖完整性：有无遗漏的模块或接口
- 业务流程覆盖度：是否覆盖核心业务链路
- 饱和式覆盖情况：正常 + 异常 + 边界是否均有用例
- 引用文档准确性：是否与设计/需求文档一致
