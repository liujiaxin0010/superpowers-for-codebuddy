# 8 维度测试设计与集成测试关注点

覆盖矩阵（正常/异常/边界/状态/组合/回归）解决「路径维度」；本文件补「质量属性维度」——8 大维度全方位覆盖。

## 8 大维度

| 维度 | 关注点 | 用例 ID 前缀 |
|---|---|---|
| 功能测试 | 各功能点是否符合预期行为 | T0xx |
| 性能测试 | 响应时间、吞吐量、资源占用 | T1xx |
| 安全测试 | 认证授权、数据保护、输入校验 | T2xx |
| 可靠性测试 | 故障恢复、容错处理、降级策略 | T3xx |
| 兼容性测试 | 不同环境、版本、浏览器 | T4xx |
| 易用性测试 | 交互流程、错误提示、操作门槛 | T5xx |
| 监控测试 | 日志输出、指标采集、告警触发 | T6xx |
| 数据一致性测试 | 数据流转、存储、同步后一致性 | T7xx |

采用**饱和式覆盖策略**：优先正常路径，再补异常和边界，逐步提升覆盖深度。

## 实现状态标注

每条用例标注当前环境可执行性，避免设计出无法执行的用例：

- ✅ 可实现：当前环境可直接执行
- ✅ 可实现(embedded)：需嵌入式模式
- ⏳ 暂不实现(remote 加速器)：需远程加速器环境，当前不具备
- ⏳ 暂不实现(多节点集群)：需集群环境，当前不具备

## 集成测试四关注点

集成测试（L2）重点关注：

| 关注点 | 验证什么 |
|---|---|
| 接口契约 | 调用方与被调用方的入参/出参/错误码是否一致 |
| 数据流转 | 数据在模块间传递是否完整、格式是否正确 |
| 错误传播 | 下游异常是否正确向上传播、是否被合理处理 |
| 并发场景 | 多线程/多进程访问下的竞态条件和数据安全 |

## 用例 ID 规范

按维度编号（`T{维度}{序号}`，如 `T001` 功能、`T201` 安全），便于管理和按维度筛选。每条用例最后一列标「引用文档」标注来源（如「数据接入流程.md」），实现测试用例与设计文档双向可追溯。
