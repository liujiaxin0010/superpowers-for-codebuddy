# PostgreSQL 问题分诊矩阵

本文件只在还没确定问题类别、或准备给出明确诊断结论时读取。

## 查询慢

最小证据：

1. `EXPLAIN ANALYZE`
2. 过滤列、关联列、排序列
3. 是否存在大页码 `OFFSET`
4. 是否存在应用层循环查库

默认先查：

1. 顺序扫描
2. 错误分页
3. `SELECT *`
4. N+1

## 写入 / 事务慢

最小证据：

1. 事务范围
2. 批量大小
3. 是否有不必要索引或触发器
4. 锁等待情况

默认先查：

1. 长事务
2. 逐条写入
3. 热点行更新

## 锁争用 / 死锁

最小证据：

1. 阻塞链或锁等待信息
2. 涉及的 SQL
3. 事务边界
4. 加锁顺序

默认先查：

1. 事务过长
2. 同批行加锁顺序不一致
3. DDL 与 DML 混跑

## RLS / 安全

最小证据：

1. RLS 策略文本
2. 会话变量来源
3. 受影响查询
4. 是否有对应索引

默认先查：

1. 复杂子查询
2. 复杂函数
3. 策略条件与索引不匹配

## 线上 DDL / 连接池

最小证据：

1. 表规模或连接规模
2. 流量窗口
3. 回退方式
4. 变更范围

默认先查：

1. 大表是否该 `CONCURRENTLY`
2. 连接是否泄漏
3. 超时与池大小是否失衡

## 不能直接拍板的情况

1. 没有 `EXPLAIN ANALYZE` 却要给慢查询根因
2. 没有流量和回退信息却要给线上 DDL 建议
3. 没有策略文本却要判断 RLS 根因
