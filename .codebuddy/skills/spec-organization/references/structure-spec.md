# spec/ 目录结构、命名与合规检查

## 存放策略

| 层级 | 存放位置 | 说明 |
|---|---|---|
| 系统级 | 独立设计仓库 | 子系统架构、组件划分、跨组件交互等顶层设计 |
| 组件级 | 代码仓库 `spec/` 目录 | 一个组件对应一个代码仓库，完整设计文档放仓库根的 `spec/` 下 |

## 组件级目录结构

```
{组件代码仓库}/
├── spec/
│   └── {子组件名}/                # 【必须 README.md】
│       ├── README.md              # 概述、功能清单、架构图、模块划分
│       ├── 技术选型.md            # 【可选】涉及技术选型决策时
│       ├── openapi.yaml           # 【可选】对外暴露 REST 接口时（用 openapi-creator）
│       ├── 数据库设计.md          # 【可选】涉及数据库时
│       ├── 核心流程/              # 【不含 README】命名：{业务名称}流程.md
│       │   └── {业务名称}流程.md
│       ├── 测试用例/              # 【不含 README】命名：{功能名称}测试套.md
│       │   └── {功能名称}测试套.md
│       ├── 配置设计/              # 【不含 README】【可选】
│       │   ├── 配置说明.md
│       │   └── config.yaml
│       └── 子模块/
│           └── {子模块名}/        # 【必须 README.md】
│               ├── README.md      # 概述、功能清单、架构图、类划分
│               ├── 核心流程/
│               └── 测试用例/      # 【可选】
├── src/
└── ...
```

## 文件说明

| 文件 | 层级 | 必须/可选 | 说明 |
|---|---|---|---|
| README.md | 子组件 + 子模块 | 必须 | 子组件含模块划分，子模块含类划分 |
| 技术选型.md | 子组件 | 可选 | 选型决策及理由 |
| openapi.yaml | 子组件 | 可选 | 对外 REST 接口契约 |
| 数据库设计.md | 子组件 | 可选 | 表结构设计 |
| 核心流程/ | 子组件 + 子模块 | — | `{业务名称}流程.md` |
| 测试用例/ | 子组件 + 子模块 | — | `{功能名称}测试套.md`；子模块下可选 |
| 配置设计/ | 子组件 | 可选 | 配置说明.md + 配置样例 |

## 组织原则

1. 按层级组织，不跨层引用
2. 必须文件不省略（每个子组件/子模块必须有 README.md）
3. 可选文件按需创建
4. 命名规范统一（`{业务名称}流程.md` / `{功能名称}测试套.md`）
5. 子目录（核心流程/、测试用例/、配置设计/）不含 README.md
6. 先固化再迭代
7. 唯一事实来源（规格与代码同仓，禁多份副本）
8. 文档链接构建知识网络（每个文档含到上级与同级相关文档的链接）
9. Merge-Back 回填（临时规格验证后回填主文档，见 `ssot-principles.md`）

## 结构合规检查（/spec-check）

| 检查项 | 内容 |
|---|---|
| 必须文件 | 每个子组件/子模块目录下是否存在 README.md |
| 命名规范 | 核心流程 `{业务名称}流程.md`、测试套 `{功能名称}测试套.md` |
| 目录层级 | 文件是否放在正确层级，无跨层错放 |
| 可选文件 | 可选文件是否仅在涉及时创建 |
| 整改流程 | 发现不合规给整改建议，经 Boss 确认后才执行调整 |
