**你的任务是：基于变更检测，精准同步 `CONTEXT.md`；源码文件一行都不改。**

## 🚫 核心禁令（硬约束）

- ❌ **禁止修改任何源码文件**（含头部三行注释）。源码头部注释属于 `/doc-init` 的一次性初始化产物，`/doc-sync` 不负责同步
- ❌ **禁止向上无限级联**：更新仅限变更文件的**直接父目录** `CONTEXT.md`；上层 `CONTEXT.md` 仅在"子模块一句话概述变了"时才动
- ❌ **禁止"间接影响"扩散修改**：间接影响只体现在 `CONTEXT.md §⑤ 调用关系` 中，不触发其他文件的头部注释修改

## 执行步骤

**第零步：环境检查**
1. 执行 GitNexus 可用性检查
2. 若索引过期，执行 `npx gitnexus analyze` 更新
3. 若不可用，降级到 `git diff + 手动阅读受影响目录` 的方案（见 project-reading.md）

**第一步：确定同步范围（智能增量）**
- 指定了路径 → 使用 **模式 A** 分析该路径下文件
- 未指定路径 → 使用 **模式 C**（变更影响分析）：
  1. 获取 `git diff` 变更文件列表
  2. 计算变更文件的**直接父目录**集合（这是本次 `CONTEXT.md` 更新范围，上限）
  3. 间接受影响文件**不在本次写入范围**——仅用于更新所在父目录的 §⑤ 调用关系

**第二步：文件类型过滤**
沿用 `code-documentation.md` 的自动生成代码识别（三种方式：头部标记 / 文件名模式 / 目录名）

**第三步：通过 GitNexus 获取最新关系数据**
对每个待更新的 `CONTEXT.md` 所在目录，使用 **模式 B + A** 获取最新：
- 模块内文件清单（与 §④ Inventory 对比）
- 调用关系（与 §⑤ 对比）
- blast radius（决定是否仍属于 L1 核心模块）

**第四步：按节分类生成差异报告**

| 节 | 差异检测逻辑 |
|---|---|
| § ① 地位 | 模块在图谱中的 Community 角色是否变化 |
| § ② 逻辑 | 是否有新增/删除的 Process 节点 |
| § ③ 约束 | 只由 AI 辅助——代码中的校验逻辑/配置常量是否新增变化 |
| § ④ Inventory | 新增/删除/重命名的文件 → 行增删；INPUT/OUTPUT 变化 → 行内列更新 |
| § ⑤ 调用关系 | Mermaid 图节点和边是否需要更新；blast radius 数值更新 |
| § ⑥ 决策与踩坑 | **只读不改**——此节只有 Boss 可追加，AI 不得擅自修改 |
| § ⑦-⑨（L1） | 数据流 / 扩展点 / 故障模式节按需刷新，⑧ 扩展点的"不动区"需 Boss 确认 |
| § ⑩-⑫（L2） | 按需刷新 |

**第五步：AI 精准补充验证（仅针对 🟡 标记项）**

**第六步：向 Boss 汇报差异（表格形式）**

报告格式必须包含：
- 本次变更涉及的 `CONTEXT.md` 文件列表（按目录分组）
- 每个文件按节分类的差异行
- **显式声明**："本次不修改任何源码文件"——证明禁令已遵守

**第七步：等待 Boss 确认后批量更新 `CONTEXT.md`**
- 只写 `CONTEXT.md` 文件；如果 PR 里出现源码文件被修改，立即 BLOCKED 并回报

**第八步：汇报更新结果**
- 更新了哪些 `CONTEXT.md`
- 源码文件改动数：**必须为 0**
- 如有需要 Boss 决策的 §⑥/§⑧ 条目，单独列出
